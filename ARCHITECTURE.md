# Support Assistant - Архитектура проекта

## Обзор

Support Assistant — это интеллектуальная система на базе искусственного интеллекта, предназначенная для помощи операторам банка ВТБ в анализе и ответах на запросы клиентов. Система использует передовые модели машинного обучения для классификации текста и генерации ответов, предоставляя помощь сотрудникам поддержки в реальном времени.

## Компонентная архитектура

### 1. Фронтенд (Frontend Layer)

#### Технологический стек
- **Веб-сервер**: Nginx (Alpine Linux)
- **Фронтенд**: Vanilla JavaScript, HTML5, CSS3
- **UI Фреймворк**: Кастомная дизайн-система в стиле ВТБ

#### Ключевые возможности
- **Анализ в реальном времени**: Обработка запросов клиентов на лету
- **Интерактивный интерфейс**: Навигация на основе вкладок (Анализ/История)
- **Адаптивный дизайн**: Мобильная верстка с брендингом ВТБ
- **Локальное хранилище**: Управление историей обращений на стороне клиента
- **Система обратной связи**: Интерфейс оценки и корректировки оператором

### 2. Бэкенд (Backend Layer)

#### Технологический стек
- **Фреймворк**: FastAPI (Python 3.11)
- **ASGI Сервер**: Uvicorn со стандартными расширениями
- **AI Интеграция**: Клиент для API, совместимого с OpenAI
- **Обработка данных**: Pandas, NumPy, Scikit-learn

#### Основные компоненты

##### 2.1 API Слой (`app/main.py`)
```python
# Ключевые эндпоинты
POST /analyze          # Обработка запросов клиентов
POST /feedback         # Сбор обратной связи от операторов
GET  /health          # Проверка работоспособности
GET  /stats           # Статистика системы
```

##### 2.2 Слой AI Моделей (`models/model_final.py`)

**Ключевые AI компоненты:**

1. **База знаний (`KnowledgeBase`)**
   - Управляет обучающими данными и эмбеддингами (векторными представлениями)
   - Обрабатывает нормализацию текста и нечеткое сравнение
   - Поддерживает транслитерацию (Английский ↔ Русский)
   - Кэширует эмбеддинги для производительности

2. **Извлечение сущностей (`EntityExtractor`)**
   - Идентифицирует финансовые сущности в запросах
   - Поддерживает нечеткое сравнение ключевых слов
   - Работает с общей банковской терминологией

3. **Классификатор поддержки (`OptimizedSupportClassifier`)**
   - Семантический поиск с использованием эмбеддингов
   - Резервный вариант на основе ключевых слов
   - Классификация с помощью LLM для сложных случаев
   - Кэширование запросов для производительности

4. **Генератор ответов (`TemplateBasedResponseGenerator`)**
   - Генерация ответов на основе шаблонов
   - Несколько вариантов ответов для операторов
   - Выбор ответа на основе уверенности модели

5. **Непрерывное обучение (`ContinuousLearning`)**
   - Собирает обратную связь от операторов
   - Анализирует точность классификации
   - Запускает переобучение модели
   - Аналитика производительности

### 3. Внешние сервисы

#### Интеграция с AI сервисами

## Архитектура развертывания

### Разработка и продакшен

Система использует Docker контейнеры:
- **Бэкенд**: FastAPI приложение на порту 8000
- **Фронтенд**: Nginx для статических файлов на порту 3000
- **Внешние сервисы**: Интеграция с SciBox API

## Безопасность

### 1. Сетевая безопасность
- **Изоляция контейнеров**: Каждый сервис работает в изолированных контейнерах
- **Сегментация сети**: Сервисы общаются через Docker сети
- **Открытые порты**: Только необходимые порты открыты для хоста

### 2. Безопасность приложения
- **CORS конфигурация**: Ограниченные кросс-доменные запросы
- **Ограничение запросов**: Регулирование частоты API запросов
- **Валидация входных данных**: Модели Pydantic для проверки запросов
- **Обработка ошибок**: Безопасные сообщения об ошибках без конфиденциальных данных

## Производительность

### 1. Стратегия кэширования
- **Кэширование запросов**: LRU кэш для частых запросов
- **Кэширование эмбеддингов**: Хранение предварительно вычисленных векторных представлений
- **Нормализация текста**: Кэшированная обработка нормализованного текста

### 2. Масштабируемость
- **Без состояния**: Бэкенд сервисы не хранят состояние
- **Горизонтальное масштабирование**: Поддержка нескольких экземпляров бэкенда
- **Балансировка нагрузки**: Nginx может распределять запросы

## Итог по технологическому стеку

| Слой | Технологии | Назначение |
|-------|------------|---------|
| **Фронтенд** | HTML5, CSS3, Vanilla JS | Пользовательский интерфейс |

| **AI/ML** | SciBox API, Scikit-learn | Обработка текста, классификация |
| **Данные** | JSON, Local Storage | База знаний, клиентское хранилище |

| **Мониторинг** | Health checks, Логи | Мониторинг системы |

## Перспективы развития архитектуры

### 1. Улучшения масштабируемости
- **Микросервисы**: Разделение на более мелкие, сфокусированные сервисы
- **Очереди сообщений**: Асинхронная обработка с Redis/RabbitMQ
- **База данных**: PostgreSQL для постоянного хранения данных
- **Кэширование**: Redis для распределенного кэширования

### 2. Улучшения AI/ML
- **Версионирование моделей**: A/B тестирование для обновлений моделей
- **Хранилище фич**: Централизованное управление признаками
- **Мониторинг моделей**: Отслеживание производительности моделей в реальном времени
